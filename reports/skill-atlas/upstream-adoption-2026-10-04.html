Design code structure

✓ Adapted Local owner: design-code-structure.

Why adapt. A design can look coherent while a contributor copying one nearby caller still bypasses validation or forgets a second registry. Pstack's updated architect makes that partial-context risk explicit.

Result. The design names an existing module, type, lint, test, or build mechanism that enforces an intended boundary. Related registries derive from an authority or have their actual relationship checked. One maintained route is preferred for the same contract.

Local judgment. UI and billing lists may represent different sets. Supported protocol surfaces and migration paths stay until their consumers can move. Distributed writers retain their real transaction invariant. A design-only request names the mechanism without implementing it.

Observed exercise. A payment design included an importable ledger bypass, duplicated provider lists, a legitimate UI subset, an ignored partner contract, two writers, and v1/v2 coexistence. The separate established-label request kept its existing pattern.

Evidence before claiming automatic enforcement

✓ Adapted Local owner: workflow-to-skill; instruction writing remains with agent-instructions.

Why adapt. Turning a repeated correction into another reminder can leave the invalid path intact. A proposed check also needs to reject the actual failure while allowing a legitimate neighboring case.

Result. The handoff names the existing enforcement owner, a failing case and rejection cause, and a valid acceptance case. An observed failure is preferred; a reconstruction must be labeled. Missing proof stays unresolved. Project checks belong to the authorized project owner, while the instruction writer owns a skill-bundled helper.

Local judgment. Extraction alone does not modify CI or product code. Preserve rationale and exceptions until real enforcement coverage is established. Preventing new violations and migrating old debt remain separately scoped. No fixed recurrence quota, global history audit, mandatory rule table, or exception-expiry policy was adopted.

Observed exercise. The existing layer checker rejected an application import that bypassed tenant validation and accepted both the public API and an intentional internal-test exception. The handoff preserved the quality lane and separated accepted debt from new violations.

Shared performance evidence, with the caller in control

✓ Adapted Criteria and verdict: verify. Diagnosis and experiment: debug and prototype.

Who does what
OwnerResponsibility
debugMeasure the reported problem, investigate its cause, and repair only within the active authority. Memory regressions also select the performance branch.
prototypeBuild and run the bounded experiment, retain its harness and results, and give a recommendation within the evidence.
verifyAssess completed correct work, comparison conditions, variation, and resource plausibility. Return the verdict to the active caller without restarting its task.
Project harness or recipeOwn execution details. A supplied benchmark packet can be assessed without a project recipe; missing application coverage remains explicit.

Why adapt. Scheduling unfinished work, returning errors faster, saturating the load driver, or changing build settings can produce an impressive number that does not support the claimed improvement.

Result. The new conditional reference checks measurement boundaries and outputs, counts errors separately, retains repetitions and variation, separates diagnostic profiling from scored timings, and distinguishes local measurements from application gains. Adoption decisions must resolve or justify material configuration differences; merely documenting a handicap is insufficient.

Local judgment. A single labeled observation can be useful. A bounded deployed-configuration difference does not require proof of its bottleneck. Warm caches can be the intended workload. There is no universal run count, Linux command requirement, single-number PR format, tuning loop, or benchmark gate for ordinary functional checks. Both callers retain minimum measurement criteria when verify is unavailable.

Observed exercises. The packet contains unfinished asynchronous work, fast failures, a constrained load driver, valid deployed and end-to-end comparisons, an invalid adoption inference, a microbenchmark overclaim, a rough observation, and a functional near-miss. Executable cases cover pending-task completion and deterministic retained memory, plus the unavailable-specialist path.
