Make module boundaries and duplicated registries enforceable

Adapt · first

Architect now asks whether a plausible edit made from partial context remains correct across the repository. Its design screen adds split ownership, competing ways to do a task, importable internals and hand-synchronized lists.

Already covered. The local skill already models invariant ownership, change locality, private representations, derived state and compatible migrations. Those parts need no second rule set.

Proposed local action. Revise the existing Compare and choose screen to ask whether a plausible edit made with partial context remains correct repository-wide. Check parallel paths that keep gaining callers, intended-private imports that consumers can still reach, and manually synchronized registries. Prefer one maintained route where its contract allows; derive related projections or check their defined relationship. Use available module, type, lint, test or build mechanisms to enforce intended boundaries, without requiring a new toolchain.

Adaptation boundary. Keep legitimate distributed writers and independently owned state behind the real invariant. Retain compatibility layers, supported platform variants and staged migrations until their consumers can move. Do not require one physical writer, forbid intentional protocol exports, or delete every alternative in the same change.

Make a proposed guardrail demonstrate the mistake it prevents

Adapt · optional second step

The new correct skill groups repeated mistakes and prefers structural enforcement before instructions. It requires a new check to reject a real historical mistake.

Already covered. workflow-to-skill already separates deterministic operations from judgment, inspects existing enforcement, and routes to the current owner. agent-instructions already requires meaningful success/failure cases and matched evidence. Proposed local action. If adopted, add a narrow requirement to the automation evidence handoff: supply a minimized historical failure when available, the existing enforcement owner, and a valid nearby case the check must still allow. Adaptation boundary. Delete a rule only after checking actual enforcement coverage and retaining its scope, reason and exceptions. Keep explanatory context for judgment and exceptions; docs are not universally removable once a check exists.

Defer · optional future adoption

Later perf guidance orders hypotheses from avoiding unnecessary work through cheaper execution; hillclimb borrows that order while retaining its own stopping condition.
