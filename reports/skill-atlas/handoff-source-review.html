Handoff · source review

Keep it portable.
Keep it small.

Use Matt Pocock's document exporter as the base. Replace its literal Skill tool reference with portable wording. A few explicit continuation details can improve the result without importing a session-management system.

Correction to the earlier atlas. The user accepts /tmp. Its difference from .tmp is not a reason to adapt the skill. A generic handoff document also has no reason to know Orca or any other named host.

The necessary portability edit

Matt already has Codex metadata and an explicitly invoked, create-only scope. The literal instruction to use a particular Skill tool is the concrete host dependency. Portable wording is enough to resolve that issue.

The useful improvements

Make the next action, relevant decisions, observed state, verification and accessible references explicit. These are quality improvements, not compatibility requirements. Matt's own guide already discusses several of them.

Direct adoption remains reasonable for a short manually requested summary. For the intended development workflow, a small adaptation makes the continuation contract clearer. An indexed archive, automatic restart or full create/discover/resume system is not currently justified.

A proposed contract, not a created skill

Enough context to continue

The document should be shaped around the recipient's next task. Existing plans and evidence remain the source of detail.

  • Current objective and relevant scope or authorization, with user decisions distinguished from agent inference.
  • Actual done, partial and pending state; relevant repository/revision and dirty state only when useful.
  • Next useful action and why; blockers, failed approaches and traps only when they affect continuation.
  • Applicable verification evidence and remaining acceptance checks; an unrun check is not a pass.
  • Pointers to existing artifacts with what matters there, whether the receiver can access them, and any material lifetime limitation.
Completion boundary. The artifact exists, its location is known and its material dependencies are clear. That does not establish that another agent received it, started work or took ownership.

A side-task export can leave the original session running. A code task may need branch, revision and dirty-state details; a research conversation may not. Suggested skills are recommendations to resolve through the receiver's available capabilities.

Creating the file does not itself authorize a commit, push, worktree change, agent cancellation, publication or new session. Current user instructions govern continuation. A selected old document supplies context; it does not silently expand that authority.

The existing host may already preserve enough context. In that case, a second export adds little. A portable file remains useful when context crosses tools, filesystems, people or a focused side-task boundary.

Access and lifetime decide

/tmp is a valid choice

The useful question is whether the receiver can read the document and the artifacts it references when needed. Changing the folder name does not answer that.

Storage choices for a continuation document
SituationSuitable choiceWhat matters
Near-term pickup on the same filesystemOS temporary storage, including /tmp, or a permitted checkout .tmp location.Return the actual path and preserve required references until pickup. Temporary storage is not a retention guarantee.
Another machine, container or inaccessible checkoutA receiver-accessible artifact or an explicitly authorized transfer.Check the required referenced files too. A local absolute path is not a transfer.
Delayed pickup or durable retentionA destination with the required lifetime.Use the requested destination and applicable environment constraints. Do not impose a universal home directory or managed store.

pstack's own pause procedure also uses a /tmp resume-note example. Compound accepts explicit destinations outside its temporary store. Neither fact makes storage policy the core of handoff.

Independent review, reconciled against sources

Two model perspectives

Independent source consultations completed with Codex · gpt-6-astra · Max and Claude · claude-fable-5-1 · Max. Both received the same request and source corpus in fresh contexts, without the coordinator's preferred conclusion.

  • Both reviewers support removing the /tmp objection and keeping named host orchestration outside the document capability. The user explicitly accepts OS temporary storage.
  • Matt SKILL.md line 10 explicitly says Skill tool, contrary to Fable's no-tool-names claim. Adopt Astra's minimal wording correction; keep useful existing Codex metadata.
  • Use Matt as the base. Decision provenance, relevant state, evidence and the next action are useful refinements, not prerequisites for portability. Git details are conditional. The old atlas recommendation does not itself establish a mandatory user contract.
  • Keep exact output location, useful artifact pointers, current-state distinctions and decision attribution. Do not import managed discovery or an unconditional resume stop. Compound is prose-based; no separate transport script is required.
  • A created document is a separate outcome from receipt or execution ownership. A generic skill can serve host consumers without naming them. Local protocol changes and Fable's reported missing integration target remain outside this review scope.
  • GSD workflow says delete on read; its guided resume prompt says retain until completion or supersession. Record the conflict and avoid copying its lifecycle. Needed recovery context should remain available to the task that still depends on it.
  • Do not claim .tmp is inherently invisible from another worktree, /tmp is shared across all sandboxes, or every Codex session clears temp. Access and retention depend on the receiving environment. The user's handoff-specific preference needs no global instruction edit.
  • The original repository list is only one snapshot. Existing TypeScript and CI/CD overlays already cover the 19-repository corpus. This review adds handoff-specific depth; it does not claim those repositories were never previously covered.
  • Compound contains a scenario definition for stopping on resume and text-contract tests. No run result was inspected or reproduced, so neither is claimed as observed behavior. Binary string probes do not establish supported host commands and are not used in the recommendation.
  • agent-profile plugin metadata declares MIT, but no license file appears in the pinned inventory. The recommendation borrows ideas; this task does not copy or redistribute its instruction text.
  • Preserve explicit invocation and the focus on context that must travel. Do not enforce a fixed line count, exact four-case taxonomy, mandatory Git template, new memory system or required session shutdown. Related pause, plan and recall workflows keep their own owners.

These are textual source reviews. They do not demonstrate automatic skill activation, successful context transfer or improved downstream behavior. No handoff workflow was run.
