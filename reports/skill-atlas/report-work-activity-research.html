report-work-activity: a concise HTML report with meaningful counts and evidence you can revisit.

Skill atlasSynthetic exampleDesignSelected sourcesAll repositoriesValidation
The example is synthetic: 20 merged work PRs across two repositories, plus 3 and 2 open-source PRs in their own rows. No private account activity was collected during authoring.

One skill, two useful views

Historical activity

Yesterday, the previous calendar week or month, or an explicit period, resolved in your timezone. The actual merge, review, closure, send, response or message time decides inclusion. Work has totals and repository rows. Open source has a row for each repository; public employer projects remain work.

Current outstanding work

Assignments, explicit commitments, unanswered requests and proposed next steps stay distinguishable. The snapshot checks later completion, cancellation, reassignment or reopening, including older open items. A request is not an accepted promise; an invitation is not attendance.

These views share identities, collection and evidence. Keeping one entrypoint avoids collecting everything twice while preserving separate historical and current-state rules.

A missing optional connector reduces coverage. Missing Luna blocks the affected extraction instead of silently changing the requested model. A relevant partial source or unresolved attribution prevents an exact total; a known other actor can legitimately be excluded.

Follow-up without recollection

The private bundle contains index.html, repository detail pages, readable evidence, manifest.json, report.json, events.jsonl, metrics.json and obligations.json. The default durable root is ~/.local/share/work-activity; configured destinations take precedence. Follow-up reads the snapshot first and refreshes only named current-state questions.

Connected-source coverage
