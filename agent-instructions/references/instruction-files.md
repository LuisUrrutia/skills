# Persistent instruction files

## Find the source and its scope

Inspect the target, effective ancestor and nested files, imports, links and
generated-file notices. Edit the declared canonical source, preserving adapters.
Resolve a symlink's target before writing.

| Intended scope | Placement |
| --- | --- |
| Personal, across projects | Configured personal source |
| Repository | Repository source |
| Subsystem or directory | Effective local instructions or scoped reference |
| Conditional procedure | Referenced guide or existing specialist |
| Current request | Task context unless persistence was requested |

Preserve filenames and case; creating both `CLAUDE.md` and `claude.md` does
not solve portability. Verify a new host entrypoint's supported name and import
syntax. Resolve uncertain loading and precedence from the configured host.

Imports may expand at startup, so smaller files need not reduce loaded context.
Conditional headings or XML attributes neither load files nor raise authority.
Verify moved rules still reach their tasks, including hosts that omit nested files
when launched at the root. Preserve working adapters unless their change is in scope.

## Make the requested change

Place related rules together with their conditions and material exceptions.
Reconcile authorized changes; preserve unrelated rules and out-of-scope overrides.

Ground commands, package managers and paths in current definitions. Inspect
working directory, prerequisites and effects before running bounded authorized
checks. Deployment, destructive setup or external writes need their own authority.
Distinguish configured, executed and successful commands; repair stale commands
from evidence.

Keep the entrypoint focused on project purpose, necessary commands with when to
run them and non-obvious prerequisites or effects, domain constraints, conventions
and routes to context. Configuration owns bare script lists. Put extensive
background in existing documentation with a concrete reading condition, not only
temporary research notes.

Instruction files need no new skill. A single incident or task permission does
not establish global policy; an explicit user change to a standing rule does.

## Check the result

Read the result with its callers and effective scope. Check imports, adapters
and narrower files for conflicting copies. Exercise in-scope and out-of-scope
tasks for changed behavior. Report inspected and exercised evidence; saving files
does not prove a running host reloaded them.
