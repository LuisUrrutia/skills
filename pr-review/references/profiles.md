# PR intake and profile use

Read at PR intake. The PR URL identifies its target `owner/repo`; a fork
checkout's `gh repo view` may identify a different repository. Capture the PR
metadata first, then resolve the target's private profile as `review-code-changes`
directs.

Beyond what that review reads, use the matched profile's Comment bindings for
wording and Author names for the conversation title.

A profile's Rules name the guides to pass through `--rules`. The brief records
every passed file's authority class from the auditor protocol, the paths it
covers, and its scope as its own text sets it. An owner convention is shown by
how authors resolved the owning reviewer's comments on those paths; a review
practice guide is one the parent supplies.

`snapshot.py` shares only the profile sections workers may receive. Keep
Checkouts, Tracker access, Comment bindings and Author names with the parent,
and inspect the filtered packet for private access data before dispatch.
